# 阶段任务卡

每个阶段一张卡，结构统一：**阶段信息 → 任务清单 → 🎫 过关卡片 → 常见卡点**。

| 阶段 | 任务卡 | 执行序号 | 周次 | 工时 | 一句话目标 |
|---|---|---|---|---|---|
| 一 | [LLM API 基本功](stage-1-llm-api.md) | **#01–#12** | 1~3 | 32h | 像调用一个"不确定的 RPC"一样调用大模型 |
| 二 | [RAG 全链路](stage-2-rag.md) | **#13–#21** | 4~6 | 30h | 搭出一条能召回、会拒答、带引用的 RAG 链路 |
| 三 | [评估体系](stage-3-eval.md) | **#22–#26** | 7~8 | 20h | 让每一次优化都有数据支撑 |
| 四 | [Agent](stage-4-agent.md) | **#27–#33** | 9~12 | 36h | 理解 Agent 就是"带工具的循环"，并做出可控版本 |
| 五 | [生产化](stage-5-production.md) | **#34–#41** | 13~14 | 24h | 把 demo 变成敢上线的系统 |

**按序号执行，不要按阶段挑着做。** 完整顺序、优先级（P0/P1/P2）和依赖关系见 [ROADMAP.md](../ROADMAP.md)。

## 怎么用过关卡片

过关卡片分三类条件，**全部达标才算过关**：

- **🎯 硬指标**：可量化、可复现。跑一下就知道过没过，不存在"我觉得差不多"。
- **🖥 演示题**：能当着别人的面跑起来。防止"代码能跑但我不知道为什么能跑"。
- **🗣 口试题**：合上电脑，用自己的话讲清楚。防止复制粘贴式通关。

**没过就没过。** 记录卡在哪一条，下周优先补。带着漏洞往前冲的代价，在第三、第五阶段会加倍还回来。
