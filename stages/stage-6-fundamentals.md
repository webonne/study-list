# 阶段六 · 补基础 + 选方向

| | |
|---|---|
| **周次** | 第 13~14 周 |
| **预计工时** | 20 小时 |
| **前置** | 阶段五已过关 |
| **产出** | 一份原理笔记 + 一个方向性小实验（进 `labs/`） |
| **一句话目标** | 补上调优真正需要的原理，然后选定一个方向深入 |

> **语言实现**：本卡是语言无关的。具体用什么库、怎么写、会踩什么坑，见 [Java 轨道](../tracks/java.md) · [Go 轨道](../tracks/go.md)。双语分配策略见 [tracks/README.md](../tracks/README.md)。

> **为什么原理放在最后**：前面五个阶段你已经踩过足够多的坑，现在学原理是"解释我遇到过的现象"，而不是"背我用不上的概念"。
> 同样一句"注意力机制的复杂度是 O(n²)"，第一周听是天书，第十三周听是"哦，难怪长上下文那么贵"。

> **本阶段只补和调优直接相关的部分。** 不需要推导反向传播，不需要手写 Transformer。目标是：**当系统表现异常时，你能从原理层面猜到原因。**

## 任务清单（Part A：必补，约 12h）

### T6.1 Transformer / 注意力的直觉（3h）
- [ ] 读《The Illustrated Transformer》（图解，不需要数学基础）
- [ ] 理解注意力机制在做什么：每个 token 看其他所有 token
- [ ] 理解 **O(n²)** 意味着什么 → 为什么长上下文又贵又慢
- [ ] 理解 **"lost in the middle"** 的成因 → 为什么上下文顺序影响效果

**要能回答**：为什么上下文长度有限制？为什么把重要信息放中间容易被忽略？

### T6.2 Tokenizer（2h）
- [ ] 理解 token ≠ 字符 ≠ 词
- [ ] 实测：同一段内容的中文版和英文版，token 数差多少
- [ ] 理解为什么中文、代码、JSON 的 token 密度差异很大
- [ ] 理解为什么"数字母个数"这类任务模型容易错（它看到的不是字母）

**要能回答**：为什么不能用字符数估算成本？为什么换模型后 token 数会变？

### T6.3 采样与随机性（1.5h）
- [ ] temperature / top_p / top_k 各自在做什么
- [ ] 理解为什么"同样输入不同输出"，以及这对你的测试策略意味着什么
- [ ] 理解为什么设了低随机性也**不能保证完全一致**

**要能回答**：eval 分数波动的底层原因是什么？

### T6.4 Embedding 与向量相似度（2.5h）
- [ ] 理解 embedding 是什么：把文本映射成高维空间里的点
- [ ] cosine 相似度 vs 欧氏距离，什么时候用哪个
- [ ] 理解为什么"语义相近但字面不同"能被检索到，而"字面完全一致的编号"反而可能搜不到
- [ ] 理解为什么换 embedding 模型必须全量重建索引

**要能回答**：为什么纯向量检索在专有名词上会挂？（这个你阶段二已经实测过了，现在补上原理解释）

### T6.5 ANN 索引原理（3h）
- [ ] 理解精确检索 vs 近似检索（ANN）的取舍
- [ ] **HNSW 的核心参数**：
  - `m`：每个节点的连接数 → 影响索引大小和召回率
  - `ef_construction`：建索引时的搜索宽度 → 影响索引质量和构建时间
  - `ef_search`：查询时的搜索宽度 → **影响召回率和延迟，可在线调**
- [ ] **动手实验**：固定数据集，扫描 `ef_search` 从小到大，画出「召回率 vs 延迟」曲线
- [ ] 找到你的业务场景的最佳工作点

这个实验做完，你对向量库的理解会超过绝大多数只会 `INSERT` 和 `SELECT` 的使用者。

## 任务清单（Part B：选方向，约 8h）

**挑一个**深入，做一个小实验并写结论。不要贪多——两周时间做深一个，比浅尝四个有价值。

### 方向 1 · 检索深化
- Embedding 微调（用你的黄金集做训练数据）
- 稀疏向量（SPLADE）
- **GraphRAG**：适合"实体关系密集"的场景（组织架构、供应链、故障因果链）
- 多模态 RAG（图表、截图）

**适合**：你的业务数据量大、领域性强，通用 embedding 效果不够。

### 方向 2 · Agent 深化
- 多 Agent 协作与任务分解（主控 + 若干 worker，worker 用便宜模型）
- 长时程任务（跑几小时的任务怎么做检查点和恢复）
- 沙箱执行（让 Agent 写代码并安全地跑）

**适合**：你想做研发效能、自动化运维方向。

### 方向 3 · 推理与私有化部署
- vLLM / Ollama 本地部署
- 量化（模型精度与显存的取舍）
- 私有化方案的整体架构与成本核算

**适合**：你所在的公司有数据不出内网的硬要求。**国内企业这块需求很大，是很实在的差异化能力。**

### 方向 4 · 微调
- LoRA / SFT 的原理与实操
- 数据集构建（这才是微调的真正难点）
- 微调 vs RAG vs prompt 的决策框架

⚠️ **放在最后是刻意的**：90% 你以为需要微调的场景，其实是 RAG 没做好或 prompt 没写好。选这个方向前，**先诚实回答**："我的 eval 分数低，真的是模型不懂领域知识，而不是检索没召回到吗？"

## 🎫 过关卡片

### 🎯 硬指标

| # | 指标 | 达标线 |
|---|---|---|
| 1 | 原理笔记 | 五个概念（注意力 / tokenizer / 采样 / embedding / ANN）**各用自己的话写 200 字以上**，且**必须结合你前五个阶段遇到的具体现象** |
| 2 | HNSW 实验 | 产出一条「`ef_search` → 召回率 / 延迟」曲线，并给出你的选值和理由 |
| 3 | Token 实测 | 给出中文 / 英文 / 代码 / JSON 四类内容的 token 密度实测数据 |
| 4 | 方向实验 | 选定一个方向，完成一个小实验，**有假设、有数据、有结论** |
| 5 | 决策文档 | 写一份"我们该不该做 XX"的判断（XX = 你选的方向），有数据支撑 |

第 1 条的关键在于**"结合具体现象"**。写"注意力机制让模型关注相关 token"是背书；写"我们的 Agent 跑到 15 轮就变慢变贵，是因为注意力是 O(n²)，所以上下文管理不是优化项而是必需品"——这才叫理解。

### 🖥 演示题

1. 展示 HNSW 参数实验的曲线图，说明你为什么选这个工作点。
2. 用**不超过 3 分钟**，给一个完全不懂 AI 的后端同事讲清楚"RAG 为什么能工作"。
   （讲不清楚，说明你自己还没想透——这是最好的检验方式）
3. 展示方向实验的结论，说明它会如何影响你下一步的技术决策。

### 🗣 口试题（合上电脑作答）

1. 为什么上下文越长越贵，而且是**超线性**地贵？
2. 为什么中文比英文费 token？这对成本估算意味着什么？
3. 一段 3000 字的文档做 embedding，可能出什么问题？
4. `ef_search` 调大会怎样？调小会怎样？你会在什么情况下动它？
5. 什么情况下**应该**考虑微调？什么情况下微调是在掩盖真正的问题？
6. 回顾这 14 周，如果重来一次，你会怎么调整学习顺序？为什么？

最后一题没有标准答案，但它是最重要的一题——**能说清楚自己学习路径的取舍，说明你真的走完了这条路，而不是被推着走完的。**
