# 语言轨道

阶段任务卡（`stages/`）是**语言无关**的：概念、任务拆解、过关卡片对 Java 和 Go 通用。
本目录放**语言特定的实现要点**：技术选型、SDK 用法差异、各阶段的语言侧重点和坑。

| 轨道 | 文档 | 定位 |
|---|---|---|
| Java | [java.md](java.md) | 主力语言。生态最全，业务落地首选 |
| Go | [go.md](go.md) | 第二语言。Agent 运行时 / MCP Server / 高并发在线服务的更优解 |

---

## ⚠️ 先看这里：不要把 14 周的内容做两遍

两种语言全量重做，时间翻倍，但收获远不到两倍——因为**RAG 和 Agent 的难点 80% 不在语言上**（切块策略、检索质量、评估方法、prompt 设计全是语言无关的）。做两遍，你只是把同样的业务逻辑用两种语法抄了两次。

**正确的做法是按语言优势分配阶段**，让 Go 出现在它真正能带来增量的地方。

### 推荐分配

| 阶段 | Java | Go | 为什么这么分 |
|---|---|---|---|
| 一 · API 基本功 | ✅ 主力 | ✅ **也做一遍** | 代码量小、概念清晰，是学 Go 的最佳起点。同一个功能两种语言对照着写，语言差异感受最深——这一遍性价比最高 |
| 二 · RAG | ✅ 主力 | 🔶 **只做在线检索服务** | 离线解析/embedding 生态 Go 很弱，别硬上；但**并发多路召回**是 Go 的主场 |
| 三 · Eval | ✅ 主力 | ❌ **跳过** | 离线批处理，用什么语言写都一样。做两遍纯属浪费 |
| 四 · Agent | 🔶 了解 | ✅ **主力** | **Agent 运行时和 MCP Server 用 Go 明显更合适**：单二进制交付、goroutine 并行工具调用、context 级联取消 |
| 五 · 生产化 | ✅ 侧重限流/熔断/降级 | ✅ 侧重 pprof / race / goroutine 泄漏 | 两边关注点本来就不同，不算重复 |
| 六 · 基础 | — | ✅ **读 Go SDK 源码** | Go SDK 代码量小、可读性高，是学 Go 工程实践的上好材料 |

### 时间安排两个选项

| 方案 | 总周期 | 做法 | 适合 |
|---|---|---|---|
| **紧凑版**（推荐） | **14 周不变** | Go 只做阶段一和阶段四，其余单语言推进 | 想尽快把 AI 能力用起来，Go 顺带补上 |
| **完整版** | **17 周**（+3 周） | 按上表全量走 | Go 项目是你的重点，想同时把 Go 吃透 |

**先选紧凑版。** 阶段四做完，你对 Go 的掌握程度会远超预期——因为 Agent 那套东西（并发、流式、context、错误处理、接口设计）恰好把 Go 最核心的语言特性全用了一遍，而且是在真实场景里用的，比刷语法教程有效得多。

### 一条重要提醒

**不要为了"用 Go"而用 Go。** 文档解析、embedding 推理、数据清洗这类活，Go 的生态确实薄，硬写会让你在无关的地方耗掉大量时间，还得不到好结果。
正确姿势是**按职责切分服务**：Go 做在线编排层，Python/Java 做离线数据层，两边用 HTTP/gRPC 连起来。这本来就是更好的架构，不是妥协。
