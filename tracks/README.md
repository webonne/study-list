# 语言轨道

阶段任务卡（`stages/`）是**语言无关**的：概念、任务拆解、过关卡片对 Java 和 Go 通用。
本目录放**语言特定的实现要点**：技术选型、SDK 用法差异、各阶段的语言侧重点和坑。

| 轨道 | 文档 | 定位 |
|---|---|---|
| Java | [java.md](java.md) | 主力语言。生态最全，业务落地首选 |
| Go | [go.md](go.md) | 第二语言。Agent 运行时 / MCP Server / 高并发在线服务的更优解 |

**两条轨道调用的都是 DeepSeek**，走 **OpenAI 兼容协议**（`POST /chat/completions`），
字段完全一致——这让"同一个功能两种语言各写一遍"的对照价值最大化。
换成通义 / Kimi / 本地 vLLM、Ollama 只改 base-url 和模型名。

---

## ⚠️ 先看这里：不要把 14 周的内容做两遍

两种语言全量重做，时间翻倍，但收获远不到两倍——因为**RAG 和 Agent 的难点 80% 不在语言上**（切块策略、检索质量、评估方法、prompt 设计全是语言无关的）。做两遍，你只是把同样的业务逻辑用两种语法抄了两次。

**正确的做法是按语言优势分配阶段**，让 Go 出现在它真正能带来增量的地方。

### 推荐分配

| 阶段 | 执行序号 | Java | Go | 为什么这么分 |
|---|---|---|---|---|
| 一 · API 基本功 | #01–#07 / **#08–#12** | ✅ 主力 | ✅ **也做一遍** | 代码量小、概念清晰，是学 Go 的最佳起点。同一个功能两种语言对照着写，语言差异感受最深——**这是全程唯一真正重复的一段，性价比最高** |
| 二 · RAG | #13–#21 / ⊕#21+ | ✅ 主力 | 🔶 **只做在线检索服务** | 离线解析/embedding 生态 Go 很弱，别硬上；但**并发多路召回**是 Go 的主场 |
| 三 · Eval | #22–#26 | ✅ 主力 | ❌ **跳过** | 离线批处理，用什么语言写都一样。做两遍纯属浪费 |
| 四 · Agent | **#27–#33** | 🔶 了解 | ✅ **主力** | **Agent 运行时和 MCP Server 用 Go 明显更合适**：单二进制交付、goroutine 并行工具调用、context 级联取消。⚠️ 这里 Go 是**替代** Java，不是叠加，所以不会翻倍 |
| 五 · 生产化 | #34–#40 / **#41** | ✅ 侧重限流/熔断/降级 | ✅ 侧重 pprof / race / goroutine 泄漏 | 两边关注点本来就不同，不算重复 |
| 六 · 基础 | #42–#46 / ⊕#47 | — | ✅ **读标准库源码** | `context`、`errgroup`、`net/http` 的 Client，是学 Go 工程实践的上好材料 |

完整的编号顺序、优先级和依赖关系见 **[ROADMAP.md](../ROADMAP.md)**。

### 时间核算（按 [ROADMAP.md](../ROADMAP.md) 逐任务累加）

| 方案 | 总工时 | 每周 10h | 做法 |
|---|---|---|---|
| **标准版**（推荐） | **162h** | **17 周** | 按上表走，跳过 ⊕ 标记的 P2 任务 |
| **完整版** | 173h | 18 周 | 含 ⊕#21+（Go 检索服务）和 ⊕#47（读 SDK 源码） |
| **最小可行** | ~100h | 10 周 | 只做 P0，见 [ROADMAP 最小可行路径](../ROADMAP.md#最小可行路径只做-p0约-100-小时--10-周) |

**Go 只让总量增加了约 12 小时**（阶段一那一遍），因为阶段四的 Go 是替代 Java 而不是额外做一遍。
阶段四做完，你对 Go 的掌握会远超预期——Agent 那套东西（并发、流式、context、错误处理、接口设计）恰好把 Go 最核心的特性全用了一遍，而且是在真实场景里用的，比刷语法教程有效得多。

### 一条重要提醒

**不要为了"用 Go"而用 Go。** 文档解析、embedding 推理、数据清洗这类活，Go 的生态确实薄，硬写会让你在无关的地方耗掉大量时间，还得不到好结果。
正确姿势是**按职责切分服务**：Go 做在线编排层，Python/Java 做离线数据层，两边用 HTTP/gRPC 连起来。这本来就是更好的架构，不是妥协。
