## 目录结构与使用说明

```
study-list/
├── README.md          ← 你在这里：仓库使用说明
├── PROGRESS.md        ← 进度看板，唯一的"我学到哪了"的事实来源
├── plans/             ← 总体计划（为什么这么学、避坑）
├── stages/            ← 阶段任务卡 + 过关卡片（每周实际要干什么，语言无关）
├── tracks/            ← 语言轨道：Java / Go 的选型、实现要点、专属过关项
├── labs/              ← 小实验代码：一个想法一个目录，用完就扔
├── projects/          ← 正式项目代码：要维护、要演示、要写进简历
└── notes/             ← 学习笔记，按 YYYY-MM-DD-主题.md 命名
```

### `plans/` — 为什么这么学

放**总体计划**：路线设计、技术选型理由、常见误区。**低频修改**，通常只在阶段复盘后调整。
看它是为了回答"我为什么要学这个、下一步大方向是什么"。

### `stages/` — 这周具体干什么

放**阶段任务卡**，每个阶段一个文件。每张卡包含四部分：

| 部分 | 作用 |
|---|---|
| 阶段信息 | 周次、预计工时、前置条件 |
| 任务清单 | 拆到 1~4 小时粒度的具体任务，带产出物和估时 |
| **🎫 过关卡片** | **硬指标 + 演示题 + 口试题**，全部达标才算过关 |
| 常见卡点 | 提前写好的排查方向，省掉重复踩坑 |

**过关卡片是这套方法的核心。** 学习最大的陷阱是"我好像学过了"，过关卡片用可验证的标准替代这种感觉：
- **硬指标**：可量化、可复现（例如"缓存命中率 ≥ 70%"），跑一下就知道过没过。
- **演示题**：能当着别人的面跑起来，防止"代码能跑但我不知道为什么"。
- **口试题**：不看资料能讲清楚，防止"复制粘贴通过"。

**不许自己给自己放水。** 没过就回去补，或者明确记录"这条因为 XX 原因跳过"——记录下来就行，骗自己才是问题。

### `tracks/` — 用哪种语言、怎么写

`stages/` 只讲概念和标准，**不绑定语言**；`tracks/` 放语言特定的部分：技术选型、SDK 用法、各阶段侧重点、语言专属的坑和过关项。

| 轨道 | 定位 |
|---|---|
| [Java](tracks/java.md) | 主力语言。生态最全，业务落地首选 |
| [Go](tracks/go.md) | 第二语言。Agent 运行时 / MCP Server / 高并发在线服务的更优解，含**面向 Java 工程师的 Go 速成** |

⚠️ **不要把 14 周的内容用两种语言各做一遍**——时间翻倍但收获远不到两倍。
按语言优势分配阶段的具体方案见 [tracks/README.md](tracks/README.md)。

### `labs/` — 试错区

一个想法一个目录，命名 `lab-<编号>-<主题>/`，比如 `lab-03-chunk-strategy/`。
允许乱、允许硬编码、允许没有测试。**唯一要求**：每个 lab 目录下有一个 `README.md`，写清楚"我想验证什么 / 结论是什么"。三个月后你只会记得结论，不会记得代码。

### `projects/` — 正式项目

三个递进项目的代码。这里的代码要按**生产标准**写：分层、配置外置、有日志、有测试。
详见 [projects/README.md](projects/README.md)。

### `notes/` — 笔记

命名 `YYYY-MM-DD-主题.md`。建议每周至少一篇，重点写**"我原以为…实际上…"**——认知被修正的瞬间最值钱，而且最容易忘。

## 日常工作流

**每周一（10 分钟）**
1. 打开 `PROGRESS.md`，确认当前阶段。
2. 打开对应的 `stages/stage-N-*.md`，挑出本周要推进的任务。
3. 对照 `tracks/` 确认本阶段用哪种语言做、要不要做两遍。

**每天（1 小时）**
3. 做任务 → 代码进 `labs/` 或 `projects/` → 勾掉任务卡里的复选框。

**每周日（40 分钟）**
4. 写一篇 `notes/`。
5. 对照过关卡片自查：硬指标能不能跑出来？口试题能不能不看资料答出来？
6. 更新 `PROGRESS.md`。
7. 提交。

**阶段末**
8. 完整走一遍过关卡片。全过 → 在 `PROGRESS.md` 记录过关日期，进入下一阶段。
9. 没过 → 记录卡在哪一条，下周优先补这一条，**不要带着漏洞往前冲**。RAG 和 Agent 的知识是强依赖的，第三阶段的 eval 没做，第五阶段的成本优化就无从验证。

## 提交约定

保持简单，能看懂就行：

```
docs: 完成阶段二任务卡 T2.6 混合检索
feat(project-1): 接入 bge-reranker
notes: 2026-10-12 chunk 策略对比实验
chore: 更新进度看板
```

代码和笔记一起提交，别攒到周末一次性 push——真实的学习节奏本身就是记录的一部分。
